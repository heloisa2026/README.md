# README.md
## **Ciclo de Vida de um Projeto no GitHub**

## **Sessão 1: Criação e envio do projeto**

1. Entro no GitHub e crio um novo repositório, escolhendo o nome, descrição e se ele será público ou privado.
2. No computador, abro a pasta do projeto e o terminal. Uso git init para iniciar o Git e git remote add origin para conectar a pasta ao repositório do GitHub.
3. Adiciono os arquivos com git add, registro a alteração com um commit e envio para o GitHub usando git push.
4. Depois, acesso o repositório pelo navegador para conferir se os arquivos foram enviados corretamente.

## **sessão 2: README.md**

O README.md serve para explicar o projeto e facilitar o entendimento de quem acessar o repositório. Um README pode apresentar informações como:

- Título e descrição do projeto;
- Tecnologias utilizadas;
- Funcionalidades;
- Como instalar ou executar;
- Status do projeto;
- Autor e licença, quando necessário.

O README utiliza Markdown porque permite organizar o texto de forma simples, usando títulos, listas, negrito, códigos e links. Isso deixa a página mais fácil de visualizar e entender.

## **sessão 3: Atualização**

Depois de publicar o projeto, é possivel fazer alterações pelo GitHub Online, assim, posso editar arquivos diretamente pelo navegador, o que é mais indicado para mudanças pequenas.

Pelo Terminal, posso usar comandos como git add, commit e push para registrar e enviar as alterações. Também é possivel fazer isso pelo VS Code, usando a interface grafica para visualizar as mudanças, fazer commits e enviar os arquivos.

Outra opção é o GitHub Desktop, que facilita esse processo mostrando os arquivos alterados e permitindo fazer o commit e o push sem precisar usar tantos comandos.

também é importante fazer atualizações aos poucos, criando commits menores. Assim, fica mais fácil acompanhar as mudanças e encontrar erros sabendo oq foi alterado em cada etapa, ao em vez de deixar tudo acumulado para enviar de uma vez.
